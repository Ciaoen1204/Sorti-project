# 拾序市集體驗改版規格

日期：2026-10-11。狀態：使用者最新指示改為跟隨首頁配色，覆蓋先前 B 固定深綠決策；第一批改版已完成，詳見 platform-parity.md。

本輪僅新增設計文件，未修改 App、PWA 或雲端資料庫。附件描述五張參考圖，但本輪未收到原圖；下列規格依文字需求及現有程式規劃，未做逐圖視覺比對。

## 1. 現有功能及缺口

| 範圍 | 已存在的程式與行為 | 本輪改版工作 |
|---|---|---|
| 導覽 | App.tsx、platformAppearance.ts；四個底部入口。Native MarketScreen、PWA Market 直接商品瀏覽，已有訊息、購物車、我的交易 | 保留路由，精簡頂部操作，固定刊登入口 |
| 商品探索 | Native FlatList 雙欄、PWA market-grid；loadProducts 真實查詢名稱及描述、分類、價格範圍、三種排序；useMarketPage 每頁 20 筆、300ms 延遲、過期回應保護 | 圖片比例與卡片層級统一；結果總數需新增 count 查詢，不能用當頁筆數充當總數；補地區篩選 |
| 分類 | marketplace.ts 現有分類：大型家具、桌上收納、收納盒/籃、其他；歷史物品分類仍可存在 | 不能直接換成附件的六大類並造成既有商品找不到；分類方案需確認 |
| 商品詳情 | 真實商品重新載入、單張圖、價格、狀況、瑕疵、交易方式、描述、分享、聊天、購物車及直接購買 | 重排資訊；賣家現為 UUID 片段，欠缺安全公開的賣家資料讀取；相關商品未完成 |
| 舊商品 | 允許兩種交易方式皆 false；賣家可編輯商品補上設定；結帳已有缺少方式提示 | 商品詳情先阻擋購買及加購物車，改顯示「請先詢問交易方式」；自己的商品直接導向設定 |
| 刊登 | 來源、商品資訊、交易方式、預覽四階段；真實照片、物品資料帶入、條款驗證、請求識別碼防重複 | 合併為三步，第三步內含預覽；完整保留返回修改及刊登結果 |
| 我的交易 | 已有我的購買／我的刊登／銷售訂單；商品含保留狀態；角色與訂單狀態控制操作 | 改成圖片與下一步優先的列表；精簡狀態頁籤；刊登與關聯訂單互通 |
| 訊息 | 真實 conversations/messages、商品關聯、訂單入口、輪詢與訊息去重服務 | 賣家／買家名稱、頭像、訊息排列及重試一致性需補齊；未讀數缺讀取游標，不顯示假的徽章 |
| 面交 | order.meetup、提出／確認提案、双方交付旗標已存在；目前主要在訂單詳情 | 聊天接入相同訂單操作，預約卡片顯示狀態與下一步；補複製地點與外部地圖搜尋 |
| 寄送 | 實際寄件日期／物流商／追蹤碼／備註；買家確認收貨 | 寄送區塊重排，明示資料由賣家填寫；不顯示平台已驗證付款或物流 |
| 交易安全 | SQL 的版本驗證、保留、唯一有效配置、取消協商、交易問題與事件；v2 三個 RPC | 保持現有交易規則；版本衝突先刷新並說明，不自動接受更新後條款 |
| 主題 | ThemeContext 使用共用 appearance，預設淺色且保存深色偏好；PWA 共用色彩與導覽 | 擴充市集樣式而非改寫整個 App 主題；保留深色可用性 |
| FastAPI | 目前市集雲端操作集中 supabaseData.ts，FastAPI 主要處理 AI 功能 | 不新增另一套市集 API |

程式存在不代表已完成實機驗收。使用者曾回報 PWA 接單失敗，尚未提供具體錯誤；頁面內確認與模擬測試通過，不能據此宣稱正式交易問題已解決。

## 2. 視覺方案及共用元件

推薦 A：米白 #F7F6F0、白卡 #FFFFFF、深綠文字 #202A25、輔助字 #65716A、薄荷 #9AC8AE、主要按鈕深綠 #35634B 配白字。薄荷用於標籤、選取背景，避免淺底白字。

B：沿用現有深綠 #151B18、卡片 #202823、主要字 #F0F3F1、薄荷主按鈕 #9AC8AE 配深綠字。兩個方案共用版面與元件；不以橘色模仿其他品牌。

字級：頁名 24、商品價格 22–24、卡片價格 18、區塊標題 18、內文 16、輔助資訊 14。支援系統字體縮放，重要文字不固定高度截斷。頁邊 16、卡片間距 12、區塊間距 24、卡片圓角 16、欄位圓角 12；操作範圍至少 48。

共用概念元件：MarketHeader、ProductCard、DeliveryBadges、SellerSummary、OrderProgress、MeetupCard、ShipmentCard、TransactionActions、InlineState。業務資料仍由 supabaseData.ts 輸出、marketplaceOrder.ts 計算操作；兩平台各自渲染，不另建路由或狀態管理系統。

分類及排序使用水平籤與篩選面板。Native 採 Modal／底部面板，PWA 採有標題、焦點管理及返回按鈕的 dialog。交易確認顯示影響範圍與真實操作名称；不得只靠一個顏色區分狀態。

## 3. 八個頁面規格

### 01 市集首頁

頂部標題及訊息／購物車圖示、我的交易文字入口；下一列搜尋與清除；水平分類；排序和地區篩選；結果資訊；雙欄商品。卡片順序：1:1 真圖 → 名稱最多兩行 → 價格 → 狀況 → 公開地區 → 面交／寄送標籤。

「＋刊登」固定於底部主導覽上方右側，列表預留空間避免遮住最後一列。最新好物即真實最新排序，不稱 AI 推薦。附近功能先稱「地區篩選」，未取得 GPS 不顯示公里數。

首載骨架、無商品提示、搜尋無結果提示及清除篩選、錯誤重試、刷新保留合理篩選、分頁按鈕／滑到底載入。總數若未取得，顯示「已載入 N 件」，不用假總數。

### 02 商品詳情

順序：單張真圖 → 價格／名稱 → 分類與狀況 → 交易方式與費用 → 公開地區 → 賣家摘要 → 描述／瑕疵 → 同分類相關商品。圖片只有一張時沒有輪播圓點。

底部固定「聊聊」「直接購買」，購物車與分享為次要操作。已保留／售出／下架時顯示狀態並停用購買；自己的商品顯示管理；方式缺漏時提示賣家補充並提供聊天。舊內容無瑕疵說明只顯示未提供，不推斷無瑕疵。

賣家摘要只顯示公開暱稱與授權公開的頭像，無資料時「賣家」及字母／人物圖示；不取 Auth 私有 metadata 作公共查詢，不顯示認證或評價。其他商品由 seller_id 與 active 狀態篩選。

### 03 三步驟刊登

1. 選擇物品及照片：物品清單／拍照／相簿；選中已有裁切圖時預填名稱分類，仍可改。
2. 商品資訊與價格：名稱、分類、狀況、瑕疵、描述、價格；立即提示欄位錯誤，保留输入。
3. 交易方式及確認：至少一種方式；公開縣市／區或原有文字地區、面交備註、寄送說明及運費；展開預覽後確認刊登，不再跳第四步。

成功提供查看商品／我的刊登。送出期間停用重复發布，失敗保留照片與欄位。第三步返回第二步資料不得丟失。未建立草稿儲存不顯示儲存草稿。

### 04 聊天中心及聊天室

列表显示商品縮圖、對方公開名稱／圖示、最新訊息、時間。沒有讀取游標時不顯示未讀數。

聊天室上方商品摘要固定，下方關聯訂單／預約卡、訊息、輸入列；訊息依真實時間排列。鍵盤彈出保留輸入和送出入口，新訊息不強行拉走正在閱讀舊訊息的使用者。

無訂單：商品可購買時可提出購買請求。requested：查看請求及等待／接單。已接受的面交訂單：可展開提案表單並呼叫同一 market_order_action；卡片同時更新正式訂單。多筆關聯訂單需明確選擇，不用「最新一筆」默默代替。

傳送失敗保留文字和同一 client_request_id，重試不重複訊息；訂單操作也顯示失敗與重新整理。未接單的討論不稱正式預約。

### 05 面交預約

共用 MeetupCard：狀態、日期時間、文字地點、備註、商品摘要、雙方角色。狀態依資料推導：尚未安排／等待對方確認／已約定／等待交付確認／已完成。

提案方可改提新安排；對方確認最新提案版本。改提案使舊確認失效。雙方確認安排後分別「我已交付」「我已收到」，不可單方直接完成。

地點可複製；外部地圖入口使用 URL 編碼的文字搜尋，不宣稱精準定位。由使用者點擊後才把地點交給地圖供應商，確認此隱私決策後實作。提示選公開安全場所。

### 06 寄送交易

接受前等待／接單；接受後賣家看必要收件資料及填寫實際寄件資訊，買家看等待寄件；寄件後顯示日期、物流商、追蹤碼、備註及等待收貨；買家確認收到後完成。

物流區明示「賣家填寫的寄件紀錄」。沒有官方服務，不顯示動態運輸進度、超商寄件碼、平台付款保障。內部 cod 不直接對外稱已串接貨到付款。

### 07 我的交易

三个同層分頁：我的購買／我的刊登／我的銷售；不恢復大型角色切換。訂單卡優先顯示圖片、品名、總額、方式、狀態、下一步。購買篩選待回覆／進行中／完成／結束；銷售可細分待接受／待安排面交／待寄件／等待收貨；由真實欄位推導，不新增假狀態。

刊登篩選上架／保留／下架／售出，附真實數量；保留和售出不可重新上架或修改交易條款。缺少方式的舊商品顯示「補充交易方式」，進入現有編輯流程。關聯訂單入口以實際 listing_id 查詢，並遵守參與者 RLS。

### 08 共用訂單詳情

首屏狀態＋角色下一步 → 四階段進度 → 商品快照 → 交易方式與金額 → 預約或寄送卡 → 聊天 → 取消／問題 → 事件紀錄。多商品用訂單快照，不能以現價覆蓋成交條款。

底部主要動作依角色、版本、狀態、未解決問題及取消提議決定；沒有當前動作時顯示等待原因。v1 只保留既有查詢與允許的履約操作，不恢復舊結帳。所有 v2 寫入維持 RPC，不直接更新 orders.status。

## 4. 待確認的規則及資料擴充

| 決策 | 建議 | 影響 |
|---|---|---|
| 配色 | A 米白＋薄荷，保留使用者深色偏好 | 市集及關聯交易畫面；不整體改其他模組 |
| 分類 | P0 保留現有分類；六大類另設映射／遷移方案 | 改舊資料分類需另行確認，不能靠 UI 改標題 |
| 公開賣家資料 | 另設僅暴露暱稱與公開頭像的受控讀取介面 | 現有 profiles 為擁有者可讀，不可放寬全部個資 RLS；需 SQL 及頭像公開授權 |
| 地區篩選 | P0 文字篩選明示限制；P1 增加 city/district 結構欄位 | 舊自由文字需逐筆／賣家補齊，不能自行猜成精確住址 |
| 運費 | 保持同賣家同方式合單，取最高單件運費 | 已存在 SQL 規則；不在 UI 改成加總或免運門檻 |
| 付款 | 保持双方自行約定，平台不代收 | 本輪不改 cod 儲存及付款規則 |
| 外部地圖 | 點擊才使用文字搜尋，提供地點複製作替代 | 地點會交給外部服務，需確認 |

P1 收藏需 favorites 與擁有者 RLS；多圖需 listing_images、順序及 Storage 規則；雲端草稿需 listing_drafts；未讀／提醒需讀取游標及真實通知機制。可先做真實最新商品、既有物品帶入、文字地區篩選，不需假資料或 GPS。

P2 精準附近需經緯度、定位授權與空間查詢；認證需可稽核來源；物流、金流、退款需服務商和回呼；評價需完成訂單及防重复評分；推播需裝置註冊及後端投遞；個人化推薦需推薦資料与驗證。外部地圖文字搜尋可直接由現有架構提供，但不等同嵌入地圖或位置認證。

## 5. 實作批次與驗收

設計確認後分批完成，Android 与 PWA 每批同步：

1. 首頁／商品詳情／舊商品購買防護／三步刊登，保留其餘模組。
2. 我的交易／預約及寄送卡／聊天中的真實訂單操作／錯誤重試。需要 SQL 的公開資料功能另經確認。
3. 雙帳號交易測試、平台回歸、視覺檢查，打包 PWA 及 APK，記錄每種驗證的實際結果。

每頁驗收 Loading、Empty、Error、Success、Disabled、Retry、重複提交、登入、過期版本及權限。至少覆蓋以下情境：

- 可購商品／舊商品無方式／自己的商品／保留／售出／下架的按鈕正確。
- 搜尋與分類按全體資料篩選後分頁，不只篩選當頁；價格與地區組合可清除。
- 三步刊登及返回修改；無效價格、瑕疵未填、兩方式皆關閉會攔截；物品照片真實帶入。
- A 買家請求、B 賣家接單、提案與版本確認、雙方交付完成；寄送按實際寄件與收到順序完成。
- 第二買家同商品請求只有一筆被接受；有效保留不可重售；請求取消與接受後雙方協商取消。
- 未寄件、未收貨、單方交付、未解決交易問題不可過早完成。
- 聊天斷線重試不重複，正式預約與訂單一致；第三帳號和未登入不可存取私有交易。
- 訂單過期版本刷新後仍需確認；API 失敗顯示錯誤；舊訂單正常顯示。
- 小螢幕、字體放大、深淺主題、鍵盤、安全區、圖片失敗、底部操作與導覽不重疊。
- 原測驗 7 題／28 選項／4 人格與情境圖片、辨識框及裁切匯入、AI 建議、每日任務、捐贈回收不回退。

驗證層級分開記錄：自動化 UI 測試、隔離資料庫測試、雲端双帳號、Android 實機、PWA iPhone 實機。現有模擬測試不能代替使用者真實接單錯誤的診斷，也不能當作完整真機驗收。正式測試帳號與測試資料須先確認用途，避免用真實交易資料做破壞性測試。
