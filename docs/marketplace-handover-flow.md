# 面交與賣家寄送流程修訂

2026-10-11。狀態：使用者已同意規則並回報執行 SQL；兩平台程式與測試已完成。交易 API 存在並拒絕匿名操作，真實双帳號交付待驗證。

## 面交

購買請求 → 賣家接受並保留商品 → 待面交（透過獨立交易聊聊約時間與地點）→ 賣家確認「已交付商品」→ 等待買家確認 → 買家確認「已收到商品」→ 完成交易／商品售出。

移除提出、修改、確認面交安排的操作與表單，不再以 meetup.confirmed 作交付前提；歷史預約紀錄保留於資料庫。賣家交付前，買家收貨按鈕停用並提示等待賣家。交付完成後不允許普通取消，仍可提出交易問題。

畫面首屏用「待面交／等待買家確認／已完成」與角色下一步，商品、總額、交易聊聊下方固定目前主要操作。面交不顯示寄件表單、收件地址或物流進度。

這是依使用者移除預約功能要求調整的拾序流程，沒有照搬其他平台的預約或自動完成規則。沒有時間排程／線下驗證，不因約定時間已到便自動完成。

## 賣家寄送

購買請求 → 賣家接受並保留商品 → 待出貨 → 賣家實際寄出後填寫寄件日期、物流商、追蹤碼及備註 → 已出貨／待收貨 → 買家確認收到 → 已完成。

賣家在待出貨頁看必要收件資料及「填寫出貨資訊」；送出確認明示已實際寄出。買家在寄件前看等待提示，寄出後才可確認收貨。寄件資料展示為賣家填寫的資訊，無官方物流串接不虛構配送中、到店、簽收等事件。

訂單列表以待回覆／待面交／待出貨／待收貨／完成／已結束分流，但仍使用現有真實訂單狀態和交付欄位推導，不直接改寫訂單狀態。付款、合單運費、取消協商、交易問題及版本檢查沿用既有規則。

## 雙平台修改清單

- marketplaceOrder.ts：刪除可見預約操作，面交賣家先交付，買家後收貨；加入兩模式的角色狀態文字。
- Native／PWA 訂單詳情：不同進度條、主要操作、寄送資訊及面交等待說明。
- 我的購買／我的銷售：對應待面交、待出貨、待收貨資訊。
- 聊天保持獨立頁及接單後訊息篩選。
- 舊 v1 訂單保留；舊 v2 預約不再阻擋交付，歷史資料不刪除。

## 可審查的資料庫修改

`supabase/marketplace-handover-flow.sql` 僅替換既有 market_order_action，保留原有權限、版本、商品保留、取消、問題及事件邏輯。移除預約要求，禁止舊客戶端再提交預約；增加買家必須等待賣家交付的伺服器驗證。不建立其他交易 API，不刪除資料。
